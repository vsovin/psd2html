# VirshkeTech — промо-сайт: концепция решения

## Подход (почему JSON + Express, а не WordPress или БД)
1. **Vanilla JS + статичные HTML-страницы** — сайт грузится мгновенно, нет сборки, нет зависимостей в браузере, легко хостить где угодно.
2. **data.json как единственное хранилище** — объём данных мизерный (десятки записей), реляционная БД избыточна; fs.readFile/writeFile с сериализацией очереди записи даёт атомарную перезапись без гонок.
3. **Express — минимальный сервер** (один файл server.js): раздача статики из `public/` + 7 API-эндпоинтов. Никаких ORM, миграций, пулов соединений.
4. **Мини-CMS поверх того же data.json**: админ редактирует JSON через формы, сервер валидирует структуру и пишет файл. Тексты подставляются в DOM через `data-bind`-атрибуты — контент отделён от разметки без шаблонизатора.
5. **Авторизация админки**: пароль в `.env`, при логине сервер выдаёт случайный токен (хранится в памяти процесса + TTL), все admin-запросы идут с `Authorization: Bearer <token>`. Без JWT-библиотек, без сессий-хранилищ.
6. **XSS-защита**: весь вывод из data.json в DOM — только через `textContent`; в админке значения экранируются функцией `esc()`. Ввод имени/телефона валидируется на клиенте и сервере (маска телефона, длина полей).
7. **nodemailer опционален**: если SMTP_* не заданы в .env — заявка просто пишется в data.json, сервер логирует пропуск письма. Сайт работает без почты.

## Ключевые механики
- **Контент-биндинг**: элементы вида `<h1 data-bind="pages.home.heroTitle">` заполняются из `GET /api/data` скриптом `bindContent()` в script.js. Сервер отдаёт data.json без кэша (`Cache-Control: no-store`) — изменения из админки видны после F5.
- **Калькулятор → заявка**: выбранная конфигурация кладётся в `localStorage['vt_config']` и дублируется query-параметром `?cfg=<base>+<mod1>,<mod2>` (переживающий ручную печать URL). order.html читает cfg, пересчитывает сумму по ценам из data.json (серверные цены = источник истины), кладёт в скрытые поля `config` и `total`.
- **Безопасность записи**: сервер перед сохранением заявки/конфигурации **пересчитывает total по своим ценам** — клиентский price подделать нельзя.
- **Серверная валидация POST /api/order**: имя ≥2 символов, телефон нормализуется к цифрам (10–11), e-mail по regex, config — whitelist id из data.json, согласие обязательно. Ошибки возвращаются как `{error, fields}`.
- **admin/save**: принимает полный объект data.json (кроме orders — их нельзя перезаписать через save, статус меняется отдельным эндпоинтом), валидирует структуру, пишет во временный файл + `fs.renameSync` (атомарно), сохраняет `data.json.bak`.
