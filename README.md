# VirshkeTech — промо-сайт с калькулятором и мини-CMS

Многостраничный сайт (16 страниц) производителя оснастки и модулей автоматизации станков:
калькулятор комплектации ТФО-160, форма заявки с серверной валидацией, админка для
редактирования контента **без правки кода**. Весь контент живёт в одном файле `data.json`.

**Стек:** HTML5 + CSS3 + Vanilla JS (без фреймворков и сборщиков), Node.js 20+, Express,
fs (JSON-хранилище, атомарная запись), nodemailer (опционально), dotenv. Никаких БД.

---

## Быстрый старт

```bash
node -v            # нужен Node.js 20+
npm install        # express, dotenv, nodemailer
cp .env.example .env
# отредактируйте .env: как минимум ADMIN_PASSWORD (см. ниже)
npm start          # http://localhost:3000
```

`npm run dev` — то же самое, но с автоперезапуском при изменении `server.js` (`node --watch`).

Сборщика нет: `public/` — обычная статика, сервер раздаёт её напрямую.

## Как это работает

### Контент из data.json, а не из HTML

В разметке каждый редактируемый узел помечен атрибутом `data-bind`:

```html
<h1 class="hero__title" data-bind="pages.home.heroTitle">Оснастка и модули для станков</h1>
<a class="btn btn--primary" data-bind-href="site.social.telegram">Telegram</a>
<ul data-bind-list="pages.home.advantages"></ul>
```

При загрузке страницы `script.js` делает `GET /api/data` и заполняет DOM:

* текст — строго через `textContent` (HTML из данных не исполняется → нет XSS);
* ссылки — через `data-bind-href` с проверкой схемы (`http/https/tel/mailto`);
* списки (`advantages`, `specs`, `features`, `faq`) — через безопасный конструктор узлов;
* заглушка в HTML остаётся fallback, если сервер недоступен.

Сервер отдаёт `data.json` с `Cache-Control: no-store`, поэтому правка из админки видна
на сайте сразу после обновления страницы.

### Калькулятор → заявка

Цены баз и модулей берутся **только** из `data.json` (раздел `calculator`), в коде их нет.
Живой пересчёт суммы и список выбранных позиций — на каждое изменение radio/checkbox.

«Оформить заказ» делает две вещи: пишет конфигурацию в `localStorage['vt_config']`
и переходит на `/order.html?cfg=pro+chuck,robot` (query переживает ручную печать URL
и открытые вкладки). Приоритет источника на странице заявки: `?cfg=` → `?product=` → `localStorage`.

### Форма заявки

Клиент: имя ≥ 2 символов, телефон по маске `+7 (___) ___-__-__` (11 цифр), e-mail по regex,
обязательный чекбокс согласия. Сервер повторяет всю валидацию и **пересчитывает сумму сам**
по id базы/модулей из `data.json` — подставить в заявку свою цену нельзя; несуществующие
или выключенные (`active: false`) позиции отбрасываются. Поля срезаются по длине,
управляющие символы удаляются, опасные URL-схемы (`javascript:` и др.) обнуляются.

Далее: запись в `data.json.orders` → (если настроен SMTP) письмо на `ORDER_EMAIL` →
(если задан `WEBHOOK_URL`) POST в Telegram/CRM. Ошибка отправки письма не отменяет заявку:
она уже сохранена, факт логируется. Ответ `200 {ok, id, total}` → клиент редиректит на
`/thanks.html?id=N`; `400` → тексты ошибок показываются прямо под полями.

### Мини-CMS (`/admin.html`)

Вкладки: **Контакты** · **Тексты** (все страницы) · **Калькулятор** (таблицы баз и модулей:
название / цена / активен / добавить / удалить) · **Изделия** (карточки каталога: название,
короткое описание, цена, ссылка, URL картинки) · **Заявки** (фильтр по статусу
new/in-progress/done, смена статуса, экспорт CSV).

«Сохранить всё» отправляет собранный объект на `POST /api/admin/save`; сервер точечно
сливает присланные разделы (`mergeById` сохраняет поля, не представленные в форме, например
`url` у изделий) и делает атомарную запись: `data.json.tmp` → `fsync` → `rename`,
предварительно сохранив `data.json.bak`.

## Вход в админку

1. Откройте `http://localhost:3000/admin.html`.
2. Введите значение `ADMIN_PASSWORD` из `.env`.
3. Сервер выдаст случайный токен (`crypto.randomBytes(32)`), он лежит в
   `localStorage['vt_admin_token']`; все admin-запросы идут с заголовком `Authorization: Bearer <token>`.

Защита: токен хранится в памяти процесса, TTL 8 часов со скользящим продлением;
перебор пароля ограничен — 8 попыток с одного IP за 15 минут, далее `429`.
После рестарта сервера нужно войти заново (осознанно: секреты не пишутся на диск).

## Как поменять пароль

```bash
nano .env                 # ADMIN_PASSWORD=новый-длинный-пароль
pkill -f "node server.js" && npm start     # перезапуск обязателен
```

Сравнение пароля идёт через `timingSafeEqual` по SHA-256 — timing-атака исключена.
Рекомендуемая длина — 16+ символов; пароль не должен совпадать с паролем почты.

## Как настроить email (опционально)

Без SMTP сайт работает полностью: заявки пишутся в `data.json` и видны в админке.
Для писем заполните в `.env`:

```ini
SMTP_HOST=smtp.your-provider.ru
SMTP_PORT=465               # 465 = implicit TLS, 587 = STARTTLS
SMTP_USER=noreply@virshketech.com
SMTP_PASS=app-password      # пароль приложения, не основной пароль ящика
MAIL_FROM="VirshkeTech <noreply@virshketech.com>"
ORDER_EMAIL=sales@virshketech.com
WEBHOOK_URL=                # необязательно: бот/CRM, получит JSON заявки
```

Проверка настройки: `curl localhost:3000/api/health` → `{"ok":true,"mail":true}`.
Gmail/Yandex требуют «пароль приложения»; для продакшена лучше свой SMTP или сервис
(Mailgun/SMTP2GO), иначе письма могут попадать в спам.

## Публичные API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/data` | публичный контент; раздел `orders` **не отдаётся** |
| POST | `/api/order` | приём заявки (валидация + серверный пересчёт суммы) |
| POST | `/api/admin/login` | `{password}` → `{token, expiresIn}` |
| POST | `/api/admin/logout` | инвалидация токена |
| GET | `/api/admin/session` | проверка живости сессии |
| GET | `/api/admin/data` | полный data.json, включая заявки |
| POST | `/api/admin/save` | частичное обновление контента/калькулятора/изделий |
| GET | `/api/admin/orders` | заявки, фильтр `?status=new\|in-progress\|done` |
| POST | `/api/admin/orders/:id/status` | `{status}` → смена статуса |
| GET | `/api/admin/orders/export.csv` | CSV с BOM и `;` (открывается в Excel) |
| GET | `/api/health` | `{ok, mail}` — живость сервера и настройки SMTP |

Все `/api/admin/*` кроме `login` требуют Bearer-токен, иначе `401`.

## Запуск в продакшене

```bash
pm2 start server.js --name virshketech && pm2 save && pm2 startup   # постоянный процесс
chown $USER:$USER data.json && chmod 600 data.json .env             # права на запись
```

Можно и systemd-юнитом: `WorkingDirectory=<путь к проекту>`, `ExecStart=node server.js`,
`EnvironmentFile=<путь>/.env`, `Restart=always`.

Обязательно поставьте HTTPS (nginx/caddy reverse proxy на `localhost:3000`): токен админки
и данные формы по http передаются открытым текстом. На nginx достаточно
`client_max_body_size 256k` — тела запросов заведомо маленькие.

Резервная копия — файл `data.json` (рядом всегда лежит `data.json.bak`). Для отката:
`cp data.json.bak data.json`, перезапуск не нужен — сервер читает файл на каждый запрос.

## Тесты

```bash
node server.js &                        # нужен запущенный сервер на :3000
npm i --no-save jsdom && node tests/uitest.mjs
```

Прогон проверяет 32 сценария: логин/токен/вкладки/CRUD модулей/заявки в админке, рендер
калькулятора из данных и пересчёт сумм, перенос конфигурации на страницу заявки, клиентскую
валидацию формы, заполнение `data-bind` на главной. Текущий результат — **32 passed, 0 failed**.
Дополнительно API проверен curl-ом: `401` без токена, `400` на невалидную заявку, отбрасывание
несуществующих модулей, очистка опасных URL-схем при сохранении, корректный CSV.

## Что редактирует владелец (без программиста)

Через `/admin.html`: телефоны/e-mail/адрес/часы работы/соцсети/реквизиты · заголовки и тексты
всех страниц · преимущества · характеристики, особенности и FAQ изделий · цены и состав
калькулятора (добавить/удалить/выключить модуль) · карточки каталога и URL картинок ·
просмотр заявок, их статусы, выгрузка в CSV.

Требует правки файлов: добавление **новой** страницы (нужен HTML-файл), изменение дизайна,
структуры меню, юридические документы.

## Требуется от заказчика (плейсхолдеры)

Позиции ниже помечены в `data.json` квадратными скобками `[...]` либо являются техническими
заглушками. Заменять — через админку (тексты/цены/контакты/картинки) либо правкой `data.json`.

### Контакты и реквизиты
1. Реальный телефон (`site.phone` = `+7 (345) 111-22-33`, `site.phoneRaw` = `+70000000000`).
2. Почта для заявок (`site.email`, `ORDER_EMAIL` в `.env`).
3. Фактический адрес производства/офиса (`site.address` = `[АДРЕС] …`).
4. Часы работы (`site.workHours` — предположение: МСК+2).
5. Ссылки соцсетей (`site.social.telegram` = `t.me/virshketech`, `whatsapp` = `wa.me/70000000000`,
   `youtube` пусто).
6. Юридические реквизиты: ИНН/КПП/ОГРН, расчётные счета, банк, гендиректор
   (`site.inn` = `[ИНН/ОГРН]`, блок `pages.contacts.requisites` = `[ИНН/КПП]`, `[АДРЕС]`).
7. Карта/схема проезда — вместо неё текстовая заметка `pages.contacts.mapNote`.

### Изображения и бренд
8. **Логотип** — в шапке/подвале текстовое начертание `VirshkeTech`, графического файла нет.
9. **Фото изделий** — все 8 карточек указывают на `/assets/img/placeholder.svg`; нужны реальные
   фото ТФО-160, модуля патрона, автозажима тисков, задней бабки, робота, УДГ, зубрёжки,
   резьборезного станка (рекомендуется 1200×800, JPG/WebP, ~150 КБ).
10. Hero-изображение главной (`pages.home.heroImage`) — заглушка.
11. Иконки преимуществ — SVG-заглушки в разметке.
12. Favicon и Open Graph для расшаривания ссылок — не подготовлены.

### Характеристики и цены
13. Технические характеристики ТФО-160 (`pages.tfo160.specs`) — демонстрационные значения
    (диаметр заготовки, привод, точность, масса); подтвердите паспортными данными.
14. Совместимость со стойками (`pages.tfo160.compatibility`: Fanuc, Siemens, GSK, Mazak, Okuma,
    Haas / DDCS, Mach3, LinuxCNC, Inctra, Pumotix) — сверьте список с реально поддерживаемыми.
15. Характеристики остальных изделий (`pages.{chuck,vise,tailstock,robot,udg,gear,threading}.specs`).
16. Изделия «по запросу» имеют `price: 0` (`udg`, `gear`, `threading`) — нужна реальная цена
    или явная формулировка «уточняйте».
17. **Цены калькулятора** приняты из ТЗ: база pro/manual 370 000 ₽, lite 340 000 ₽;
    модули chuck 120 000 / vise 95 000 / tailstock 140 000 / robot 350 000 ₽. Подтвердите.
18. НДС, условия оплаты, сроки поставки, гарантия — в текстах отсутствуют, добавьте в `pages.*`.
19. Документация и чертежи (`pages.tfo160.docs`) — ссылки-заглушки, нужны реальные PDF.
20. FAQ ТФО-160 (`pages.tfo160.faq`) — типовые вопросы, замените на фактические.

### Прочее
21. Демо-заявки в `data.json.orders` (id 1–2) — удалить перед публикацией.
22. Текст согласия на обработку ПД (`pages.order.agreeText`) — **требуется юридическая проверка**;
    отдельная страница «Политика конфиденциальности» не создавалась (в ТЗ не значилась).
23. Категории фильтра каталога (`filters`: `axis/module/automation/machine`) — подтвердите разбиение.
24. Домен (`virshketech.com` в примерах) — заменить на фактический.
